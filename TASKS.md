## Planning decisions and open evidence

The stack is §11's Next.js App Router, TypeScript, Tailwind, shadcn/ui, Prisma/SQLite, Vitest, with an early P0 Playwright harness extended at P1. Keep pure engines separate from persistence/services and route handlers. Separate durable LLM/source caches from resettable workspace data. Local deployment is the default: the spec defines no cloud provider. Deployment must support writable persistent SQLite files and a server runtime; a static export or ephemeral database is insufficient.

The repository currently contains no provided logo/design tokens or audio recording. T003 documents asset provenance and uses spec defaults if assets remain unavailable; T099 separately tracks the supervisor/team recording prerequisite. Do not fabricate a supplied asset or pretend a transcript is live audio.

Seed arithmetic and narrative/rule reconciliation: twenty values total ₹2.18 Cr; six implementation-effort deals total ₹62 L; the ₹2.2 Cr pitch uses presentation rounding. Five Revive plus three Warm leaves twelve Watch, not fourteen. Pin midpoint percentile rank to 100 × (count below + 0.5 × count equal) / N: Finvara has 97.5, yielding round(0.7 × 95 + 0.3 × 97.5) = 96. MediQuick (47.5) and Bharat Freight (45) never reach the best≥50 AI threshold and reliably stay Warm. Farmlink's 51 becomes 39 with NEUTRAL; NEUTRAL also breaks the initial Revive deals and post-engagement Tripnest (59), while WEAKENS can displace Finvara from #1. Thus §12.2's invariance under arbitrary AI verdicts conflicts with §7.5; retain the formulas, test varied verdicts honestly and pin validated demo verdicts in the warmed cache. Measure/calibrate only at T024 after collectors/orchestration exist, then re-check at T032/T033 and T054. Permitted seed date/value calibration cannot fix arbitrary NEUTRAL verdicts; escalate any unresolved acceptance conflict rather than changing rules. All six implementation-effort memories require missing_feature.feature_key=null: fast_onboarding is a seller proof point, not their missing-feature request.

Other source conflicts/open decisions: §6.8's “31 deals” hero contradicts §12's thirty-row CSV; T066–T068 compute actual row totals rather than hardcode 31. No ad-image provider/key is specified; optional T080 requires a documented supervisor-selected provider/config before paid integration. §9 lacks interaction provenance, historical isolation, roadmap keys and persisted clock override; the owning tasks below record minimal additive schema decisions with `// DECISION:` comments, preserving the spec's entities and product scope.

Capture's review-before-save UI (§6.4) and immediate-save route description (§10) are reconciled by an extraction preview followed by explicit confirmation using the capture endpoint/service; no memory is finalized before “Looks right.” Generic unknown offline input retains editable input and a low-confidence OTHER fallback, while known sample hashes use precomputed memories. The audit scheduler can queue five rows (§6.8) but the shared LLM semaphore admits at most four provider calls (§13). Retention/deletion/India residency, OAuth, matcher learning and paid workspaces are roadmap copy, not new product features.
